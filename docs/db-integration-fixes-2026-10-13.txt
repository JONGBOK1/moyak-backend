# 2026-10-13 DB 통합 후속 수정

후속 반영: `fix/master-db-integration`의 실행 코드·문서·테스트를 `hanbyeol`에 반영했다.
임시 DB, 스키마 조사 결과, 복제 폴더와 중첩 저장소 참조는 제외했다.
이전 hanbyeol은 `backup/hanbyeol-before-db-sync-20261013`에 추가로 보존했다.

기준은 `origin/master`의 `8eede6a`이다. 이 브랜치는 팀 DB 통합 변경을 포함한다.
현재 프로젝트에서 `fix/master-db-integration` 브랜치로 작업했으며 이전
`hanbyeol`은 `backup/hanbyeol-before-master-20261013`에 보존했다.
별도 폴더가 아니라 현재 루트의 코드가 master 기준으로 바뀌었다.

## 수정

- 메시지 POST에 선택적 `client_id`를 추가했다. 동일 상담·발신자·ID의 재전송은
  같은 메시지를 반환한다. 같은 ID에 다른 내용을 보내면 409이다.
  환자·약사 HTML은 응답 유실 후 재시도 시 같은 ID를 보낸다.
  Flutter 등 다른 클라이언트도 재시도마다 같은 `client_id`를 보내야 한다.
- Supabase의 승인 약 수령은 승인 상태 변경, `machine_inventory.stock` 1개 차감,
  `purchases` 1건 저장을 같은 트랜잭션으로 처리한다. 자판기 코드는 UUID로
  조회해 변환하며 사용자는 기존 `users.id`에 등록된 UUID여야 한다.
  미등록 사용자·자판기·재고 부족·기록 저장 실패 시 전체 롤백한다.
  SQLite의 기존 약 수령 데모는 모의 상태 변경을 유지한다.
- 의약외품 주문 생성 시 조건부 UPDATE로 재고를 예약해 동시 주문 초과 판매를 막는다.
  도중에 한 품목이라도 실패하면 주문과 재고 변경 전체를 롤백한다.
- `POST /vending/orders/{id}/cancel`은 미결제 주문의 예약 재고를 한 번만 반환한다.
  결제 화면의 취소·뒤로가기 버튼에 연결했다. 생성 후 10분 지난 미결제 주문도
  취소한다. 서버는 30초 간격 및 상품/주문 조회 시 만료를 정리한다.
  결제·취소 경합은 상태 조건부 갱신으로 한쪽만 성공한다. 결제 완료 재고는 반환하지 않는다.

## 검증 범위

공유 DB에 쓰기 테스트나 DDL은 실행하지 않았다. 새 회귀 테스트는 임시 SQLite에서
Supabase의 코드/UUID 구분 테이블을 재현하여 재고·구매 트랜잭션, 실패 롤백,
동시 주문·수령, 채팅 API 재전송, 주문 취소·만료를 확인한다.
PostgreSQL 실환경 동시성 및 실제 결제·배출기는 별도 검증 대상이다.

현재 master의 의약품 CSV 검색, 기존 UI 등 이번 세 문제 밖의 팀원 구현은 그대로이다.
이전 hanbyeol의 추가 화면/접속 상태 기능을 master에 병합한 작업은 아니다.
이전 로컬 실행 명령 대신 master의 실행 설정을 사용해야 하며, 서버 실행 전
DATABASE_URL이 시연용인지 공유 DB인지 확인한다. 이 작업에서 서버를 새로 실행하거나
Render에 배포하지 않았다.
