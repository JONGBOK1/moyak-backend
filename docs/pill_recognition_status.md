# 알약 사진 인식 — 한 장 정리 (2026-10-20)

> 개인 저장소(`moyak`)에서 측정하며 만든 문서를 옮겨 왔다. API 사용법은 `docs/pills-api.md` 를 볼 것.
> 아래 5절의 채점 스크립트(`check_pill_real.py` 등)와 시험 사진은 개인 저장소에만 있다.

## 1. 지금 어떻게 동작하나

```
사진 1장 (또는 앞면+뒷면 2장)
  │
  ├─ ① Claude(claude-opus-5-5)에게 보냄 — 원래 사진 + 가운데 확대 사진
  │     → 모양 · 색 · 각인 · 로고 여부 · 약 종류 수 를 JSON 으로 받음
  │     (안 되면 예전 방식: OpenCV 모양·색 + Google Vision 각인)
  │
  ├─ ② 식약처 DB(drug_pills 25,350개)에서 점수순 후보 검색
  │
  └─ ③ 1위가 확실하지 않으면(각인이 통째로 맞고 2위와 벌어진 게 아니면)
        상위 10개 후보의 식약처 사진을 한 장으로 모아 Claude 에게 보여주고 다시 고르게 함
```

코드: `src/pills/identify.py`(전 과정) · `vision_llm.py`(①) · `search.py`(②) · `rerank.py`(③)
API: `POST /pills/identify` — `file`(필수) + `back`(뒷면, 선택). 응답 `detected.engine`, `detected.reranked`.

## 2. 성적표 — "정답이 3위 안에 드는가"

| 시험 사진 | 처음 | **지금** | 비고 |
|---|---|---|---|
| 식약처 사진 119장 (일반의약품만) | 1위 64.7% | **1위 93.3% · 3위 안 93.3%** | API 와 같은 과정으로 잼 |
| 실사진 14장 (전체 의약품) | 3위 안 50.0% | **71.4%** | 인터넷·직접 찍은 사진, 정답 확인된 것만 |
| 실사진, **약 기준** (앞뒤 있으면 두 장으로) | — | **10개 중 9개 (90%)** | 못 찾은 1개: 엔디펜알파정(로고를 M 으로 읽음) |
| 폰 사진 흉내 59장 (전체 의약품) | 3위 안 54.2% | **69.5%** | 식약처 사진을 손바닥·책상 배경에 합성 |
| 〃 (일반의약품만) | — | **71.2%** (5위 안 74.6%) | 자판기 앱의 실제 조건 |

**목표(새 사진 3위 안 80%)는 "앞뒤 두 장을 올릴 때" 기준으로 넘었다(90%).**
사진 한 장만 올리면 70% 안팎이다 — 남은 실패는 대부분 한 장에 정보가 없는 경우다(아래 4절).

## 3. 이번에 한 개선과 효과

| 개선 | 무엇이 나아졌나 |
|---|---|
| **후보 사진 비교(재순위)** | 실사진 3위 안 64 → 71%, 합성 1위 49 → 66%. 로고 약끼리 동점(아셀렉스), 짧은 각인('50'), 일부만 읽은 각인(KJ CX10) 을 가름 |
| **가운데 확대 사진 같이 보내기** | 폰 사진은 알약이 작아 900px 로 줄이면 각인이 뭉개짐. 실사진 57 → 64% |
| **로고와 글자 구분 지침** | 'D CT' 의 꾸민 D 를 로고로 → 디카테오 4위 → 1위 |
| **앞면·뒷면 두 장 올리기** | 앞면이 로고뿐인 약(쿠티아핀·산화마그네슘) — 한 장으론 못 찾고 두 장이면 1위 |
| **각인 점수 3가지** | 부분일치는 덮은 비율만큼 / 읽은 조각이 전부 들어 있으면 가산 / 1↔I, 2↔Z 같은 헷갈리는 글자 인정. 식약처 500장 1위 88.6 → 90.8% |
| **"서로 다른 약이 섞임" 안내** | 두 약을 한 장에 찍으면 알려 줌 |

## 4. 남은 실패 — 왜 못 찾나

- **한 면만 찍었고 그 면이 로고뿐이거나 숫자뿐** — 쿠티아핀 앞면(로고), 뒷면('50' 은 수십 개 약에 있다). → 앞뒤 두 장이면 풀린다.
- **로고를 글자로 잘못 읽음** — 산화마그네슘 뒷면을 'DHP', 엔디펜알파 '로고+1' 을 'M1'.
- **용량만 다른 같은 약** — 앞면 각인이 같으면 뒷면 없이는 못 가른다(디카테오 400 / 엘씨).
- **흐린 작은 한글 인쇄** — 합성 사진에서 '이젠이' → '이원10'.

## 5. 직접 시험하는 법

- 화면: 서버를 띄우고 `/pill-test` (사진 두 장까지 끌어다 놓기), 앱 챗봇 화면 `/app/chatbot/` 의 "+" 버튼
  - 정답이 전문의약품이면 화면의 **"일반의약품만" 을 끄고** 올릴 것
- 숫자로 재기 (캐시가 있으면 무료):
  ```
  python scripts/check_pill_real.py                    # 실사진 (data/test_photos_real/정답.json)
  python scripts/check_pill_real.py --set synth --otc  # 폰 사진 흉내
  python scripts/check_pill_real.py --set mfds --otc   # 식약처 119장
  python scripts/make_synth_photos.py --n 60           # 폰 사진 흉내 다시 만들기
  ```
- **실사진을 늘리려면**: `data/test_photos_real/` 에 사진을 넣고 `정답.json` 에 item_seq 를 적는다.
  앞뒤 쌍은 키를 `"앞.jpg+뒤.jpg"` 로.

## 6. 비용 (claude-opus-5-5, $4/$20 per 1M tokens)

- 판정 1번: 입력 약 3,000 / 출력 약 70 토큰 ≈ **1.4센트**
- 재순위(필요할 때만, 실사진에선 절반 이상): 약 1.2센트
- **사진 1장당 평균 약 2센트, 월 500장 ≈ 10달러.** 끄려면 `PILL_RERANK=false`.

## 7. 한계 — 숫자를 읽을 때 주의

- **실사진이 14장뿐**이다. 몇 장 차이로 퍼센트가 크게 움직인다. 네이버 지식인은 이 작업 환경에서 접근이
  막혀 있어 더 모으지 못했다 — 사진을 더 넣어 주면 같은 명령으로 바로 잴 수 있다.
- **폰 사진 흉내는 진짜 사진이 아니다.** 반사·초점·각인 음영은 흉내 내지 못한다.
- 재순위는 식약처 사진을 서버가 받아 와야 한다. 해외 서버(Render)에서 식약처 사이트가 안 열리면
  재순위만 조용히 건너뛴다(배포 후 확인 필요). Claude 가 식약처 주소를 직접 받는 것은 시간 초과였다.
- 이 PC 는 Anthropic 으로 큰 사진을 보낼 때 연결이 자주 끊긴다 → 끊기면 줄여서 한 번 더 보낸다.
