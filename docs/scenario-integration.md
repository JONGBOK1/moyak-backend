# Flutter + 약사 + 키오스크 시나리오 통합

GitHub `hanbyeol`의 사용자 흐름을 기준으로 기존 Flutter 사용자 앱을 유지하고 약사·키오스크 HTML을 연결했다. 기존 인증 기반 실시간 채팅, 음성 업로드 API, 양측 동의, 약사 검토 후 요약 공개 기능은 유지한다. GitHub의 간단한 채팅·요약 구현으로 교체하지 않는다.

## 실행

백엔드 폴더에서:

```powershell
.\venv\Scripts\python.exe -m pip install -r requirements.txt
.\venv\Scripts\python.exe scripts/run_consult_demo.py
```

Flutter 변경 후에는 `E:\Moyak\moyak-front`에서 `flutter build web --base-href /app/`을 실행한다.

- 사용자: http://127.0.0.1:8001/app/
- 약사: http://127.0.0.1:8001/pharmacist
- 키오스크: http://127.0.0.1:8001/kiosk/start/
- PC QR 시연: http://127.0.0.1:8001/kiosk/pairing/

## 시연 순서

1. Flutter 앱에서 로그인 화면을 지나 상담 화면의 상담 시작 버튼을 누른다. 사용자 계정은 현재 로컬 시연용이며 실제 로그인 인증은 아니다.
2. 약사 화면에서 대기 상담의 **상담 연결 · 영상/채팅/요약 열기**를 누른다. 새 창에 동일 상담의 약사 Flutter 화면이 열린다. 팝업 허용이 필요하다.
3. 사용자와 약사가 영상 연결 버튼으로 동일 Daily 방에 들어가고 같은 화면에서 채팅한다. Daily 키가 필요하다. 약사 배정 전에는 대기 취소가 가능하다.
4. 약사 대시보드에서 약품과 가격을 선택해 승인하거나 사유를 입력해 거절한다. 요약이 필요하면 양측 동의 및 대화 기록을 남기고 약사 Flutter 화면에서 종료한다. 요약 초안은 약사 검토·공개 후 사용자에게 보인다.
5. 사용자는 구매 허가서·QR 탭에서 승인 약품을 확인한다. 키오스크 pairing 화면의 **QR 내용 복사**를 눌러 앱 QR 입력란에 붙여넣고 연결한다. 복사 후 60초 내 연결한다. 또는 앱에서 QR 카메라 화면을 연다.
6. 키오스크가 연결 완료 화면으로 이동하면 승인 약품 구매 → 장바구니 → 모의 결제 → 모의 수령으로 진행한다.
7. 의약외품은 키오스크의 즉시 구매 목록에서 별도 장바구니·모의 결제·수령으로 진행한다.

## 데이터와 적용 범위

- 상담·구매·키오스크 거래는 `data/consult-demo.db`에 저장한다. 서버는 localhost에서만 접근 가능하다.
- 기존 로컬 DB에 가격·결제일·페어링 컬럼과 상품·주문 테이블을 추가한다. 기존 상담/메시지를 삭제하지 않는다.
- 지도는 기존 Supabase 자판기 위치·재고를 읽기 전용으로 조회한다. 키오스크 시연 재고는 별도 SQLite 상품이며 실제 Supabase 재고가 아니다.
- 공유 Supabase에는 이번 작업으로 DDL이나 거래 데이터를 쓰지 않는다. 실서비스 전 `approved_purchases`, `vending_machines`, `machine_inventory` 및 기존 구매 테이블의 실제 컬럼·제약과 매핑을 확정하고 별도 마이그레이션해야 한다.
- 새 시나리오 라우터는 `src.api.demo`에만 연결했다. 실제 로그인, 키오스크 기기 인증, PG 결제·환불, 실제 배출기 제어와 거래 재시도 처리는 별도 운영 연동이 필요하다.
- 약사 약품 자동완성과 의약품 목록·상세는 Supabase를 읽기 전용으로 조회한다. `drugs`를 우선하며 기존 CSV에만 있던 9개 코드는 `drug_permissions`에서 보완한다. 허가 테이블의 나머지 품목을 검색에 일괄 추가하지 않는다. 가격·재고 거래 통합은 별도 작업이다.
- Flutter 음성 녹음 업로드 UI와 챗봇 선행 상담은 이번 직접 약사 상담 흐름에 포함하지 않았다. 기존 음성 업로드/전사 백엔드는 유지한다.
- AI 요약은 실제 OpenAI 계정 사용 한도가 있어야 생성된다. 최근 확인된 크레딧 부족 상태에서는 실패 상태와 재시도를 표시하며 가짜 요약을 생성하지 않는다.
- 이 변경은 로컬 통합이며 GitHub에 새로 푸시하지 않았다.

## 검증

### AI 챗봇 화면 연결

Flutter 채팅 탭은 `/chat`에 질문과 최근 성공한 대화 20개 메시지를 전달한다. 전송 버튼·Enter 전송, 요청 중 표시, 중복 전송 방지, 답변 근거 펼치기, 오류 안내 및 입력 복구를 지원한다. 약사와의 실시간 채팅과 별도 기능이다. 로컬 서버에도 기존 RAG 라우터를 연결했으며 첫 질문 시 OpenAI/Pinecone 클라이언트를 준비한다. OpenAI 사용 한도·크레딧과 Pinecone 검색 인덱스가 유효해야 실제 답변이 생성된다. 자동 테스트는 모의 응답을 사용하며 유료 AI 응답 성공을 의미하지 않는다.

`tests/test_consult_demo.py`에 사용자 접근 제어, 대기 취소, 약사 연결과 채팅, 승인 가격, QR 연결, 결제 전 배출 차단, 중복 결제·배출 차단, 의약외품 재고 흐름을 추가했다. 기존 상담·AI·지도·약품 테스트와 함께 확인한다. 실제 카드 결제·배출 장치·물리 카메라 테스트는 해당하지 않는다.
