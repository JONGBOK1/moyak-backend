# 이름 입력과 마이페이지 표시

- Flutter 실제 소스: `E:\Moyak\moyak-front`.
- 회원가입은 한 화면에서 **이름 → 아이디·중복확인 → 비밀번호 → 비밀번호 확인 → 회원가입** 순서.
- 로그인 아이디는 기존대로 `users.nickname`, 사용자 이름은 기존 `users.name`에 저장한다. Supabase 스키마 변경은 없다.
- `POST /auth/signup` 요청에 `name`을 추가. 서버는 앞뒤 공백 제거 후 1~40자 및 제어문자를 검사한다.
- 이전 클라이언트 호환을 위해 서버는 이름 생략을 허용하지만, 새 Flutter 가입 화면은 이름을 필수 입력받는다.
- 가입·로그인 응답 `user.name`, `GET /auth/me`의 `name`으로 이름을 전달한다.
- Flutter 세션이 이름을 보관하고 마이페이지에서 표시한다. 로그아웃 시 지운다. 기존 이름 없는 계정은 로그인 아이디로 표시한다.
- 기존 로컬 SQLite `users`에만 이름 컬럼을 보완할 수 있도록 했다. PostgreSQL 자동 변경은 하지 않는다.
- 가입 및 저장 테스트는 임시 SQLite와 모의 Auth로 실행했으며, 실제 Supabase에 테스트 회원을 생성하지 않았다.
- Render 반영 전에는 로컬 서버 주소로 테스트해야 한다. 기존 APK에 코드 변경이 자동 반영되지는 않는다.

참고사항 오류 조사 (2026-10-25): 사용자는 실제 로그인 후 발생했다고 확인했다. 로컬 서버는 실제 DB 계정의 인증을 포함한 `GET /auth/me`와 `GET /auth/me/care-profile` 모두 HTTP 200이고 참고사항 응답 타입도 정상이다. 반면 Render의 `GET /auth/me/care-profile`는 인증 없이 조회했을 때 HTTP 404와 `{"detail":"Not Found"}`를 반환했다. 해당 API가 있는 서버라면 인증 없는 요청은 401이어야 한다. 따라서 Render 연결 APK라면 백엔드 배포 반영이 필요하며, 앱에서는 이 404를 서버 업데이트 안내로 표시한다. 이 조사에서 DB 쓰기·Render 배포·Git push는 하지 않았다. USB 로컬 연결 앱에서 발생했다면 기기의 정확한 오류를 추가로 확인해야 한다.

기기 재현: 사용자는 USB 실행이었다고 답했고, 실제 기기 화면에서 `Not Found`를 확인했다. 같은 시점의 로그인·참고사항 요청은 로컬 서버 로그에 도착하지 않았다. USB 연결만으로 API 주소가 로컬로 바뀌지는 않는다. 재연결 시 ADB reverse도 사라져 복구했다. 로컬 테스트는 백엔드를 켠 뒤 `powershell -File scripts/run-phone-local.ps1`로 실행하면 API 경로 존재 확인, USB 포트 연결, 로컬 API 주소 지정이 함께 적용된다.
