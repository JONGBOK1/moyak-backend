# 알약 사진 인식 API

알약 사진 한 장으로 어떤 약인지 후보를 찾는다. (작성: 선우 — DB·알약 인식 담당)

로그인은 필요 없다. 약을 찾아보는 것 자체는 개인정보와 무관하고, 자판기 앞에서 바로 쓸 수 있어야 한다.

## 어떻게 동작하나

```
사진 → ① 알약 영역 찾기 → ② 모양·색 판별 → ③ 각인 읽기 → ④ drug_pills 조회 → ⑤ 점수순 후보
```

① **알약 영역**: 테두리 색을 배경으로 보고 그와 다른 덩어리를 찾는다. 식약처 사진은 흰 배경이 아니라
   **파란 모눈종이**라 "흰색 = 배경"으로 가정하면 실패한다. 한 장에 앞뒤 두 알이 찍혀 있어 최대 3개까지 집는다.

② **모양·색**: 가로세로비·원형도·사각형 채움률로 모양을, 식약처 라벨 사진에서 **실제로 측정한** HSV 기준값과의
   거리로 색을 정한다. 꼭짓점 개수는 쓰지 않는다 — 재 보니 원형 8.4개, 타원형 7.9개, 장방형 7.9개로 구별이 안 됐다.

③ **각인**: Google Cloud Vision. 흑백 변환 → 짧은 변 400px로 확대 → CLAHE(국소 대비)를 거쳐 보낸다.
   키가 없으면 조용히 건너뛰고 모양·색만으로 후보를 낸다.

④ **조회**: Supabase `drug_pills`를 **읽기 전용**으로 본다. 판별이 틀려도 후보에는 남도록 **인접색·인접모양까지**
   함께 조회하고, 순위로 가른다.

⑤ **점수**: 모양 0.30 / 색 0.25 / 각인 일치 0.45 (부분일치 0.25, 한 글자 차이 0.15) / 비율 0.08.

## 실측 정확도 (식약처 사진, 일반의약품)

같은 사진 119장으로 잰 값이다.

| | 값 |
|---|---|
| 모양 | 88.2% |
| 색 | 76.5% |
| **후보 안에 정답 (Google Vision)** | **81.5%** |
| 1위가 정답 | 59.7% |
| 상위 5위 안 | 79.0% |
| 평균 후보 수 | 11.6개 |

각인을 무엇으로 읽느냐에 따라:

| 각인 | 후보에 정답 | 1위 정답 |
|---|---|---|
| 안 읽음 (모양·색만) | 9.2% | 0.0% |
| easyocr (오픈소스) | 70.0% | 48.3% |
| **Google Vision** | **81.5%** | **59.7%** |
| DB 에서 가져옴 | 91.6% | 78.2% |

맨 아랫줄은 **OCR 이 완벽할 때의 상한선**이지 도달 가능한 값이 아니다.
Google 과 상한선 사이 10pp 가 아직 못 읽는 각인이다.

**각인이 읽히느냐가 전부다.** 모양·색은 거들 뿐이다.

남은 실패 18건의 원인: 각인 오독 7 · 못 읽음 6 · 한글 각인 4 · 색 1 · **모양 0**.

## 엔드포인트

### `POST /pills/identify`

`multipart/form-data` 로 사진 한 장(`file`, JPEG/PNG, 8MB 이하). IP당 20회/분·300회/일.

쿼리 파라미터
- `otc_only` (기본 `true`) — 일반의약품만. 자판기에서 파는 건 일반의약품뿐이고, 후보가
  25,350개 → 5,587개로 줄어 정확도가 크게 오른다.
- `limit` (기본 10, 최대 50)

응답
```json
{
  "detected": {
    "shape": "장방형", "color": "주황",
    "imprint": "BR NBS", "aspect": 1.84, "confidence": 0.75
  },
  "candidates": [
    {
      "item_seq": "198000235", "item_name": "노브라민캡슐5밀리그람",
      "entp_name": "...", "drug_shape": "장방형", "color_class1": "주황",
      "print_front": "BR", "print_back": "NBS",
      "item_image": "https://...", "etc_otc_name": "일반의약품",
      "score": 0.83, "matched": ["모양", "색", "각인 일치"]
    }
  ],
  "note": "각인을 읽지 못해 모양과 색으로만 찾았습니다. 후보가 많을 수 있습니다."
}
```

- `note` 는 있으면 화면에 그대로 보여주면 된다. 없으면 `null`.
- `matched` 는 "무엇이 맞아서 올라온 후보인지"다. 화면에 뱃지로 띄우기 좋다.

**후보 1위를 정답으로 단정하면 안 된다.** 1위 정확도가 60%라 다섯 중 둘은 틀린다.
사진과 함께 여러 개를 보여주고 사용자가 고르게 하는 것이 맞다.

오류
| 코드 | 언제 |
|---|---|
| 400 | 빈 파일 / 이미지가 아님 |
| 413 | 8MB 초과 |
| 429 | 요청량 초과 |
| 503 | DB 주소 미설정, OpenCV 미설치, DB 조회 실패 |

## 챗봇에 붙일 때

사용자가 사진을 보내면 `/pills/identify`로 후보를 받아, 사용자가 고른 약의 `item_name`을
질문에 넣어 기존 `/chat`을 부르면 된다.

```
사용자: (알약 사진)
  → POST /pills/identify
  → "이 중에 어떤 약인가요?" + 후보 5개를 사진과 함께 표시
사용자: (2번 선택)
  → POST /chat  {"question": "타이레놀정500밀리그람은 어떤 약이야?"}
```

알약 인식은 **약을 특정하는 단계**이고, 그 뒤 설명·병용금기·추천은 기존 RAG 체인이 그대로 한다.

## 테스트 페이지

`GET /pill-test` — 사진을 올려 판별 결과와 후보를 바로 확인한다. `/pills/identify`를 그대로 호출하므로
챗봇이 보는 것과 같은 응답이다.

## 설정

```
GOOGLE_VISION_API_KEY=   # 각인 읽기. 비우면 모양·색만으로 후보를 낸다
PILL_DATABASE_URL=       # 비우면 DRUG_DATABASE_URL → MAP_DATABASE_URL 순으로 사용
```

Google Vision은 월 1,000건까지 무료인데 **사진 한 장에 앞뒤 조각 2개를 보내므로 월 500장까지**가
무료다. 시연 정도는 여유가 있지만 벤치마크를 반복해서 돌리면 금방 넘는다.
결제 수단 등록이 필요하고, 한국 계정은 선불 입금과 신분증 확인을 요구한다(2026-10-17 활성화 완료).
키가 없어도 API는 동작하며 `note`로 "각인을 읽지 못했다"고 알려준다.

오픈소스 대체(easyocr)도 코드에 있으나 `requirements.txt`에는 넣지 않았다 — torch까지 끌고 와서
무겁고, 실측 정확도가 Google 대비 낮다. 설치돼 있으면 Google 실패 시 자동으로 대신 쓴다.

## 측정 도구

고치기 전후를 숫자로 비교할 때 쓴다. 추측으로 고치면 안 된다 — 색 판별을 손으로 고쳤다가
76.5% → 68.9% 로 떨어뜨린 적이 있다.

```
python scripts/check_pill_search.py --ocr google          # 사진→후보 전 과정
python scripts/check_pill_search.py --ocr google --miss   # 놓친 건을 원인별로
python scripts/check_pill_search.py --print               # 각인이 완벽할 때의 상한선
python scripts/check_pill_vision.py --miss                # 모양·색만
python scripts/tune_pill_ocr.py                           # 전처리 방식 비교
```

OCR 결과는 `data/ocr_cache.json` 에 저장돼 다시 쓰인다. 점수나 검색 조건만 고칠 때는 Google 을
다시 부르지 않는다. **`ocr.py` 를 고쳤으면 `--fresh` 를 붙여야** 고친 효과가 보인다.

## 준비물

`sql/015_fuzzystrmatch.sql` 을 Supabase 에 한 번 적용해야 한다. 각인 한 글자 오독을 보정하는
`levenshtein()` 이 `fuzzystrmatch` 확장에 들어 있어서, 없으면 각인 검색이 깨진다.

## 고칠 때 주의

- 각인 비교 규칙을 건드리면 `tests/test_pill_search.py`부터 돌릴 것. 거기 있는 건 전부 실제로 틀렸던 것들이다.
- 색 판별은 **측정값 기준 거리**로만 정한다. 손으로 규칙을 덧붙였다가 76.5% → 68.9%로 떨어뜨린 적이 있다.
- 각인 OCR의 언어 설정은 **엔진마다 다르다**. easyocr은 한국어를 넣으면 `allowlist`를 포기해야 하고
  영문 각인이 무너지므로(62.2% → 21.6%) 영어로 못박았다. Google은 `allowlist` 개념이 없어 그 거래가
  없고, 한글을 같이 읽게 하는 쪽이 낫다(같은 119장: 72.3% → 75.6%, 1위 49.6% → 52.9%).
