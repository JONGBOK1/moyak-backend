## 화면 흐름

1. 상담 탭/챗봇의 상담 버튼 → 기존 타이머 화면. 요청 전에는 원형 타이머에 **상담 요청하기**가 표시되고 서버 요청은 보내지 않는다.
2. 원형 타이머의 **상담 요청하기** → 기존 진행 건 조회 또는 새 상담 요청 → 같은 원에 경과 시간과 **상담 요청 취소** 표시.
3. 타이머의 **상담 요청 취소** → 확인 창 → 서버 취소가 성공한 뒤 같은 화면에서 요청 전 상태로 돌아간다.
   요청 생성 중에는 중복 요청·취소를 막는다. 생성 결과를 모르는 상태에서 화면만 닫아 요청을 남기지 않기 위함이다.
4. 약사 콘솔의 **화상 상담 입장** → 담당 약사 배정 및 Daily 입장 토큰 발급 → 새 창에서 입장.
5. 앱은 3초마다 presence 확인. 방 생성, 약사 배정, 환자 단독 접속은 실제 약사 입장으로 표시하지 않는다.
6. 실제 약사 입장을 확인하면 앱 내 알림과 입장 버튼을 표시한다. 다른 탭에서는 알림의 **상담 화면** 버튼으로 돌아온다.
7. 입장 버튼 → 카메라·마이크 확인 → 영상상담. 기존 종료·요약 공개 흐름을 사용한다.

이번 변경은 FCM, OS 알림, 백그라운드 서비스 또는 앱 종료 시 자동 취소를 추가하지 않는다.
미리보기 모드는 요청 버튼을 누른 뒤 예시 타이머를 사용한다.

## 실제 입장 판별 계약

- `POST /consultations/{id}/pharmacist-token`: 기존 약사 actor 인증 계약 사용. 다른 담당 약사·환자·취소/종료 상담은 거절.
  반환: `room_url`, `meeting_token`. 토큰은 해당 Daily 방 및 담당 약사의 해시 식별자에 연결되고 만료된다.
- `GET /consultations/{id}/presence`: 기존 응답 형식 유지.
  Daily 참가자 `userId`가 담당 약사의 토큰 식별자와 같을 때만 `pharmacist_in_room=true`.
  조회 실패는 `available=false`이며 Flutter가 입장 확인 상태를 해제한다.
- 약사는 새 콘솔 버튼을 통해 들어가야 한다. 예전 토큰 없는 방 URL로 접속하면 약사로 판별되지 않는다.
- Daily 문서: [입장 토큰](https://docs.daily.co/reference/rest-api/meeting-tokens/create-meeting-token), [방 접속자 조회](https://docs.daily.co/reference/rest-api/rooms/get-room-presence).

## 기존 Supabase 구조 사용

DB 구조는 읽기 전용으로 확인했다. 공유 DB에 테이블·컬럼 생성/변경 및 환자 데이터 쓰기는 실행하지 않았다.

| 화면 항목 | 기존 저장 위치 |
|---|---|
| 알러지·질환·임신·수유·기타 | `user_conditions`: `condition_type`, `label`, `note` |
| 직접 등록한 복용약 | `user_medications`: `drug_name`, `dosage_note`, `source=manual` |
| 구매·처방 연계 복용약 | `user_medications`: `source=purchase/prescription`, 화면에서 읽기 전용 |
| 기타 메모 | `users.care_note` |

- Flutter 마이 → **상담 참고사항 (알러지·질환·복용약)**.
- 게스트·미리보기·만료된 로그인은 참고사항 조회 API를 호출하지 않고 로그인 안내를 표시한다. 조회 오류는 다시 불러오기를 제공한다.
- `GET /auth/me/care-profile`, `PATCH /auth/me/care-profile`: 로그인 Bearer 토큰 필수. 사용자 ID는 토큰에서 결정한다.
- PATCH에는 `revision`, `care_note`, 전체 `conditions`, 전체 **직접 등록한** `medications` 목록을 보낸다.
  조회한 항목은 `id`를 유지하며 새 항목은 생략한다.
- 다른 사용자의 항목 ID 및 중복 ID는 거절. 저장은 하나의 트랜잭션으로 처리한다.
- `revision`은 `users.updated_at`이다. 이 API를 통한 동시 저장/다른 프로필 변경 시 409로 덮어쓰기를 막는다.
  외부 도구가 하위 테이블만 직접 수정하며 `users.updated_at`을 갱신하지 않으면 이 충돌 검사는 감지하지 못한다.
- 직접 등록한 복용약 삭제는 `ended_on`을 기록한다. 구매·처방 약 기록은 유지한다.
- 알러지 이름/유형 또는 약 이름을 바꾸면 기존 성분/품목 코드를 해제한다. 임의 텍스트를 자동 코드 매칭이나 안전 판정 결과로 취급하지 않는다.
- `GET /consultations/{id}/care-profile`: 배정 전 약사 또는 담당 약사가 현재 참고사항 조회.
  약사 콘솔은 5초마다 참고사항만 갱신하며 채팅/처방 입력 영역을 재생성하지 않는다.
  조회 실패는 오류로 표시하며 “등록 정보 없음”으로 바꾸지 않는다.
- 약사 콘솔의 기존 ID·역할 헤더 방식은 유지했다. 이 API의 역할 검사는 기존 actor 계약 위에서 동작하며, 약사 로그인을 새로 구현한 것은 아니다.

## 검증과 실행 시 확인

- 최초 자동 검증: 백엔드 관련 테스트 25개, Flutter 관련 테스트 38개 통과.
- 타이머 버튼·단일 회원가입·게스트 진입 개선 후: Flutter 관련 테스트 42개, 이름 저장·참고사항 백엔드 테스트 19개 통과.
- SQLite 테스트 DB와 모의 Daily 응답으로 저장·권한·입장 판별을 검증한다. 실 DB 데이터를 테스트로 변경하지 않는다.
- Flutter 위젯 테스트로 요청 전 호출 없음, 환자 단독 접속 대기, 취소, 재시도, 참고사항 저장/오류, 로그인 및 기존 화면 흐름을 확인한다.
- 실제 2기기 영상통화 및 운영 Supabase 저장은 별도 확인 필요:
  1. 이 백엔드와 Flutter를 같은 API 주소로 실행하고 환자 로그인.
  2. 참고사항 저장 후 상담 요청.
  3. 약사 콘솔에서 해당 참고사항 확인 후 **화상 상담 입장** 버튼 사용.
  4. 약사 실제 입장 전후 환자 대기/알림 상태와 취소 처리 확인.
- 새 API를 사용하려면 백엔드 재시작/배포와 수정한 Flutter 재실행이 모두 필요하다. 기존 APK에는 자동 반영되지 않는다.
